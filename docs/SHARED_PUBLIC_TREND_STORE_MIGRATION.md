# Shared public trend store — local migration handoff

Status: **Hosted API reader and opt-in collector code are implemented; SQL design is ready; timestamped migration generation, local validation, and live application are pending.**

The hosted studio must not read SQLite snapshots from a serverless deployment. This design moves public trend signals and scan status into shared Supabase tables. All signed-in workspace members may read the public feed after the API verifies workspace membership. Only the opt-in server-side trend worker writes with the server-only Supabase secret key. Browser clients receive no write grants.

## Generate the timestamped migration locally

Use the intended local repository checkout and Supabase CLI so the timestamp is generated by the CLI rather than fabricated in this session:

```powershell
supabase migration new nexus_shared_public_trend_store
```

Copy the SQL below into the newly generated migration file, then run:

```powershell
supabase db lint --local
```

Run local validation only against the local Supabase stack. Do not run `supabase db push` against the live `ai_studio` project without a separately approved migration window.

## SQL

```sql
-- Shared public trend snapshots for hosted workspaces.
-- Only the opt-in server worker may write; authenticated workspace members may read.
CREATE TABLE IF NOT EXISTS public.public_trend_signals (
  signal_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  period_type text NOT NULL CHECK (period_type IN ('daily', 'weekly')),
  region text NOT NULL CHECK (char_length(region) BETWEEN 2 AND 12),
  rank_no integer NOT NULL CHECK (rank_no > 0),
  topic text NOT NULL CHECK (char_length(btrim(topic)) BETWEEN 1 AND 500),
  source_name text NOT NULL CHECK (char_length(btrim(source_name)) BETWEEN 1 AND 120),
  source_url text CHECK (source_url IS NULL OR source_url ~ '^https://'),
  source_score bigint,
  source_score_label text,
  growth_pct integer,
  viral_score integer,
  ai_reason text,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (period_type, region, source_name, topic)
);

CREATE INDEX IF NOT EXISTS idx_public_trend_signals_feed
  ON public.public_trend_signals (period_type, rank_no, region, source_name);

CREATE TABLE IF NOT EXISTS public.public_trend_scans (
  period_type text PRIMARY KEY CHECK (period_type IN ('daily', 'weekly')),
  status text NOT NULL CHECK (status IN ('running', 'success', 'partial', 'failed')),
  started_at timestamptz,
  completed_at timestamptz,
  item_count integer NOT NULL DEFAULT 0 CHECK (item_count >= 0),
  successful_sources integer NOT NULL DEFAULT 0 CHECK (successful_sources >= 0),
  failed_sources integer NOT NULL DEFAULT 0 CHECK (failed_sources >= 0),
  source_summary jsonb NOT NULL DEFAULT '{}'::jsonb,
  updated_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE public.public_trend_signals ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.public_trend_scans ENABLE ROW LEVEL SECURITY;

REVOKE ALL ON TABLE public.public_trend_signals FROM PUBLIC, anon, authenticated;
REVOKE ALL ON TABLE public.public_trend_scans FROM PUBLIC, anon, authenticated;
GRANT SELECT ON TABLE public.public_trend_signals TO authenticated;
GRANT SELECT ON TABLE public.public_trend_scans TO authenticated;
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.public_trend_signals TO service_role;
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.public_trend_scans TO service_role;

CREATE POLICY public_trend_signals_authenticated_read
  ON public.public_trend_signals FOR SELECT TO authenticated
  USING (true);

CREATE POLICY public_trend_scans_authenticated_read
  ON public.public_trend_scans FOR SELECT TO authenticated
  USING (true);
```

## Runtime behavior

- `hosted_trend_worker.py` scans daily and weekly sources, then upserts source-attributed signals and scan health to Supabase.
- The worker is available only through the Compose `hosted` profile and remains disabled unless `NEXUS_TREND_WORKER_ENABLED=true`.
- Its SQLite working database uses the named `nexus-trend-data` volume; the Vercel request path never initializes or reads local SQLite.
- The hosted API reads only the two shared tables through the caller's verified JWT. Membership is checked before feed access.
- Signals are source-local ranks only. No cross-source popularity score or fabricated view/growth estimate is introduced.
- After a successful source scan, the worker prunes older rows for that source only after upserting the new rows. Sources that failed are not pruned, so their last known signals remain available while their failure is visible in scan metadata.
- No live database changes, worker activation, or deployment are included.
